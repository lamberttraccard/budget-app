## Dev Notes

### Project Setup Sequence

This is Story 1.1 — the very first story. There is **no existing codebase** to worry about. Only start Story 1 after reading these notes in full.

The exact initialization command:
```bash
laravel new budget-app --using=laravel/react-starter-kit
```

This uses the official `--using` flag (not `--stack=` — that flag no longer exists in Laravel 12). The installer requires the global Laravel installer to be updated first.

### Bun — Not npm/Node

All JavaScript dependency management uses **Bun**, not npm. Do not use `npm install`, `npm run dev`, or `node` directly.

```bash
# Correct
sail bun install
sail bun run dev
sail bun run build

# Wrong — never use
sail npm install
```

The `package-lock.json` must be deleted before first run. After `sail bun install`, only `bun.lock` (or `bun.lockb`) should be committed.

**CRITICAL: Always install JS deps inside Sail, not on host**
```bash
# Install inside container (correct — Linux/arm64-gnu binaries)
./vendor/bin/sail bun install

# WRONG: installing on Mac host produces macOS binaries
# bun install  ← DO NOT do this, then run sail bun run build
```
If `node_modules` was installed on macOS, delete it and run `sail bun install` to get the Linux-compatible native binaries (Rollup, etc.).

### Redis Must Be Removed from Sail

The budget-app architecture explicitly **excludes Redis** to avoid infrastructure cost (database queue driver is used instead). By running `php artisan sail:install --with=pgsql,mailpit`, Sail generates a `compose.yaml` with only those services — Redis is never added.

### PostgreSQL Image — Use pgvector/pgvector:pg18

**CRITICAL**: The standard `postgres:18-alpine` image does NOT include the pgvector extension. The `pgvector/pgvector` package registers a migration that runs `CREATE EXTENSION IF NOT EXISTS vector`. Use the official pgvector image instead:

```yaml
# compose.yaml — correct
image: 'pgvector/pgvector:pg18'

# Wrong — pgvector migration fails with this
image: 'postgres:18-alpine'
```

This was discovered during Story 1.1 implementation. All subsequent stories rely on pgvector being available.

### Tailwind 4 — CSS Config, Not tailwind.config.ts

Tailwind 4 uses **CSS-based configuration** via `@theme` directives in a CSS file, not the traditional `tailwind.config.ts`. The starter kit may generate a `tailwind.config.ts` file; this is normal but the actual customization happens in CSS. Category colors and dark theme tokens will be added in Story 1.3.

### Authentication — Starter Kit Provides It

The Laravel React starter kit ships with full authentication: login, register, password reset, email verification, two-factor auth. These are managed via Laravel Fortify + session middleware (not Sanctum tokens — those are for MCP only, added in Story 5.1).

The auth redirect (unauthenticated → `/login`) applies to protected routes like `/dashboard`. The root `/` is a public welcome page.

### Project Structure Notes

The starter kit creates the standard Laravel structure. Key paths established by this story:

```
budget-app/
├── app/Http/Controllers/      # Inertia controllers (starter kit adds Auth/)
├── resources/js/
│   ├── pages/                 # Inertia pages (starter kit adds Auth/, welcome)
│   ├── components/ui/         # shadcn/ui components
│   └── app.tsx                # Inertia app entry
├── routes/web.php             # Protected by `auth` middleware
├── compose.yaml               # PHP 8.5, pgvector/pgvector:pg18, mailpit — NO Redis
├── composer.json              # All 5 packages added
└── bun.lock                   # Bun lockfile (no package-lock.json)
```

All subsequent stories build on this structure. Do not deviate from it.

### IDE / Environment

Development environment: **Laravel Sail** (Docker). All artisan, bun, and composer commands must be prefixed with `sail`:
```bash
sail artisan ...
sail composer ...
sail bun ...
```

**WARNING: Do NOT use `composer run setup`** — that script calls bare `bun install` on the host machine (not inside Sail), which produces macOS binaries incompatible with the Linux container. Use the explicit Task 3 sequence instead: `./vendor/bin/sail up -d` then `sail bun install`.
